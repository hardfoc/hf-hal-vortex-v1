Detailed Description

Singleton managing multiple TMC9660 motor controllers on Vortex V1.

Creates the onboard TMC9660 (index 0) and allows dynamic creation of external TMC9660 devices (indices 2–3). Provides array-based access to Tmc9660Handler instances, thread-safe device registration, and board-aware CS-pin management.

Note
Call CreateOnboardDevice() before EnsureInitialized(). Host-side GPIO control pins (RST, DRV_EN, FAULTN, WAKE) are required for the TMC9660 bootloader sequence.

uint8_t  deviceIndex = ONBOARD_TMC9660_INDEX

noexcept

Command target velocity in the load (output-shaft) frame.

The value is multiplied by gear_ratio_motor_to_output (and sign-flipped if invert_output is set) before being forwarded to the silicon. With the default 1:1 mechanics this is identical to setMotorVelocity().

Convention example: a 10:1 reducer with gear_ratio_motor_to_output = 10 and setLoadVelocity(60.0, VelocityUnit::Rpm, ctx) will spin the rotor at 600 RPM so the output turns at 60 RPM.

◆ SetTmclSpiTiming()

MotorError MotorController::SetTmclSpiTiming ( const tmc9660::TmclSpiTiming &  timing,
uint8_t  deviceIndex = ONBOARD_TMC9660_INDEX 
)
noexcept

Set the SPI TMCL handshake timing for one TMC9660.

The driver polls the TMC9660's NOT_READY status instead of waiting a fixed gap (see tmc9660::TmclSpiTiming). Every device starts with the driver defaults (TmclSpiTiming{}: no frame gap, 20 to 200 us back-off, 60 polls). The value is stored per slot and applied to the driver now if it is up, and again after every (re)initialization of that slot, so it can be set before Vortex brings the motors up. Measure with the TMC9660 driver's tmcl_timing example before changing it; tmc9660::TmclSpiTiming::legacy() restores the 1000 us gap used up to driver 1.0.0.

The poll budget runs on the calling thread. Lower maxPolls for slots that are accessed from a high-priority control task.

Parameters
timingNew timing.
deviceIndexDevice index (0=onboard, 2-3=external).
Returns
SUCCESS, INVALID_DEVICE_INDEX, or INVALID_PARAMETER when the active device on that slot talks UART (the setting only affects SPI).

Visit the underlying typed TMC9660 driver by device index.

Since the TMC9660 driver is now template-based, direct pointer access is replaced by a visitor pattern. The provided function receives a reference to the typed driver (either TMC9660<HalSpiTmc9660Comm> or TMC9660<HalUartTmc9660Comm>).

Template Parameters
FuncCallable type accepting auto& (the typed driver reference)
Parameters
funcThe visitor function to execute on the driver
deviceIndexDevice index (0=onboard, 2-3=external)
Returns
The return value of func, or default-constructed if driver not available
motorController.visitDriver([](auto& driver) {
driver.motorConfig.setType(tmc9660::tmcl::MotorType::BLDC, 7);
});
